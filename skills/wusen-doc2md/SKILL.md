# 文档转 Markdown 知识库 (wusen-doc2md)

将整批文档（尤其包含复杂公式、图表、跨页表格的理工科教材、学术论文或扫描课件）整理成干净、自包含、长期可维护的 Markdown 知识库。产出同时面向人类专注阅读与智能体（Agent/RAG）精准检索。

---

## 1. 先判断，再动手（Preflight）

首次使用先从本技能目录运行 `python scripts/doctor.py`，确认当前解释器和本地依赖可用。需要云端 OCR 时加 `--require-ocr`；缺少凭证不阻止已满足依赖的本地装配与校验。环境配置见 `README.md`。以下命令中的 `scripts/` 均相对本技能目录，输入与输出路径应使用用户任务的实际路径。

**不要一上来就盲目跑 OCR。** 执行前完成四项预检，可省去大量无效等待与返工：

1. **源文件有无原生文字层？**
   - 用 PyMuPDF 的 `page.get_text()` 或 `python-pptx` 检查。
   - 有文字时先区分原生文本与旧 OCR 层；可靠原生文字可作校对基准，旧 OCR 层仍须核对，不能仅凭字符数视为真值；
   - 若 100% 纯扫描件（字符数为 0），则完全依赖 OCR，需在交付报告中说明。
2. **源文件有无内嵌原图？**
   - PPTX 优先提取 `shape.image.blob`，PDF 检查 `page.get_images()`。
   - 可独立复原整幅图时优先内嵌原图；多对象矢量图和扫描页按完整区域裁切，不能用单张位图替代整幅图。
3. **识别文档形态并执行架构分流：**
   - **长篇专著/扫描教材 (`--mode book`)**：多章节连续行文，保持原有多章节划分组织架构（`01-第一章.md`、`02-第二章.md`、`00-目录.md`），采用**几何自然流混排**（严禁将图强制提前）、**严格章节判定**（严禁将页顶首句误升 H2）、**保守保留段落边界**。详见 `references/book-workflow.md`。
   - **课件幻灯片/期末讲义 (`--mode slides`)**：一页一个独立主题，保持按讲次/课时的组织架构，图文视觉集中，优先图置顶并与 PPT 原生文字对齐。
   - **学术科研文献 (Research Document)**：期刊论文、学位论文、预印本、科技研报（来自 Zotero 或独立 PDF/Word 衍生文件）。执行单篇独立文献一体化架构：输出**学术标准命名** `{{firstCreator}} - {{year}} - {{title}}.md`、生成配套 `00-目录.md` 与 `images/`；提取并注入元数据 frontmatter；双栏排版默认保留经核对的 OCR 阅读流。详见 `references/research-documents.md`。
4. **安全交付目标路径：**
   - 默认输出到**全新的独立目录**（如 `<源目录>/<书名>-知识库` 或 `<文献学术标准名>`），严禁破坏覆盖原始文件。
   - 脚本只更新未被人工修改的生成文件，拒绝清空目录。默认只交付导航、正文 Markdown 与图片；构建状态及质检报告留在交付目录之外。

## 2. 核心执行工作流

### 步骤 1：智能切分与 OCR 识别

超长教材（建议 >200 页或 >100 MB）先切片。提交入口会强制预检：PDF 有效性、加密、页数 >600、体积 >200 MB、单批 >200 份均拒绝；分片同时受页数与体积约束：

```bash
# 1. 超长 PDF 自动切片（以 96 页为例）并生成 manifest.json 与 ids.tsv
python scripts/mineru_ocr.py split <源PDF路径> --out-root ./ocr-work --chunk-size 96

# 2. 批量提交 MinerU 云端 API（模型 vlm，开启公式与表格）
python scripts/mineru_ocr.py submit --out-root ./ocr-work --id-file ./ocr-work/ids.tsv
```

- **外文/英文教材**：须显式传入 `--language en`；该参数用于声明识别语言；识别效果仍需与原页核对，不能仅凭语言参数保证正确。
- **坐标系统**：本工具读取的 `content_list.json` 使用 **0–1000 归一化坐标**，裁图时按实际页面宽高换算；`layout.json` 的页面点坐标须先按该页宽高归一化，不能混用或写死整本书尺寸。定位图题时使用 layout 中题注本身的框，不能用所属图块框代替（见 `references/mineru-api.md`）。
- **网络回退**：若遇 `cdn-mineru.openxlab.org.cn` TLS 握手 EOF，脚本已内置公共 DoH 获取真实 IP 并使用 `curl --resolve` 绕过 fake-IP 劫持（详见 `references/mineru-api.md`）。

### 步骤 2：用原生文字校正 OCR 错字（PPTX/有文字层 PDF）

OCR 会出现形近字、同音字或英文字母误识（如“轫致辐射”误为“韧致辐射”、“ν”误为“v”）。
- 当前装配脚本支持 PPTX 按文本块位置重叠度（`overlap > 0.5`）与相似度（`sim >= 0.9`）校对；有文字层 PDF 需另外核对，不能假设已自动替换。
- 差异较大者记录在 `build-report.json` 的 `review` 字段中留待复核。

### 步骤 3：高清图表提取与资产保真

提取优先级：
1. **源文件内嵌原生图片**（最清晰）；
2. **按完整图表区域从原 PDF 至少 3 倍缩放高清裁切**（扫描件或由多个矢量/位图对象组成的图）；
3. **表格内嵌图片提取**：遇到包含 `<img src="...">` 的表格（如各章拓展学习二维码），自动转存为图片并替换为 Markdown 相对引用，避免丢失；
4. **特殊复杂结构保真**：对三角形化学键等无法用标准 LaTeX 表达的二维空间图，以及深层合并的复杂科学实验表，开启 `--keep-table-images` 保留高清原版裁图双轨备查。

- **去重**：按 SHA-256 / SHA-1 内容哈希去重，杜绝挂图讲解产生的重复资产。
- **图内标签过滤**：文字块完全落在图片区域内（重叠度 > 0.6）且小于 12 字符的标签，丢弃不重复为正文。
- **多面板碎图自动缝合与 S 编号独立隔离**：
  - **高置信度自动缝合**：`--auto-repairs`（单篇论文流程默认开启）只合并同页、同图号或明确 `(a)/(b)` 面板、空间相邻且中间无正文的碎图；必须同时提供原 PDF 与 manifest。跨栏、远距离、无题注或缺面板证据的候选只导出人工草稿，不自动合并；
  - **原图优先**：PDF 中可独立复原且未旋转、裁剪或与其他对象重叠的单张位图直接取原图，其余按完整区域至少 3 倍页面渲染裁切；PPTX 图片带裁剪、旋转、翻转或位于组合内时回退为 PDF 裁切，避免把幻灯片上隐藏的区域恢复出来；
  - **S 编号独立隔离**：自动识别 `Figure S1`、`Fig. S1`、`Table S1`、`Scheme S1`、`Supplemental/Supplementary Figure 1`、`Supplementary Note 1` 与 `附图 S1`，统一纳入 `supplemental:` 独立命名空间，杜绝与正文 `Figure 1` 发生串号或错误聚类；
  - **人工审核与兜底审计**：使用 `python scripts/audit_figures.py <raw目录> [--manifest manifest.json] --out-repairs repairs-draft.json` 导出草稿；经原页核验后可通过 `--repairs` 显式覆盖。

### 步骤 4：科学公式严谨归一化

所有公式使用 Obsidian 兼容的 LaTeX：行内 `$...$`，独立公式使用单独成行的 `$$`。处理公式前读取 `references/math-normalization.md`，其中给出完整规则与前后对照。

- 自动修复只限可确定的语法归一化；式号、未知符号、物理含义和化学结构须回源后通过 `--repairs` 修改。
- 标题保留完整行内公式；需要纯文本时采用语义等价的 Unicode，不能留下裸下划线。
- 区分公式、图片 alt 与正文图注，避免方括号、物态和不等号被 Markdown/HTML 误解析。
- 无法可靠表达的二维化学结构使用高清原图；编译成功仅证明语法通过。

### 步骤 5：组织正文结构与知识库装配

```bash
# 1. 课件模式（PPTX/幻灯片）：
python scripts/build_markdown.py --raw ./ocr-work/raw --out ./知识库 \
    --mode slides --source-dir ./课件 --pdf-dir ./课件PDF

# 2. 教材/专著模式（多批块长文档，保持多章节架构）：
python scripts/build_markdown.py --raw ./ocr-work/raw --out ./知识库 \
    --mode book --manifest ./ocr-work/manifest.json --chapters ./chapters.json \
    --pdf <整本PDF路径> --keep-table-images

# 3. 学术科研文献模式（期刊/学位论文/独立PDF，统一学术标准命名）：
python scripts/build_research_document.py --pdf <论文PDF> --raw <OCR目录> \
    --out "./科研知识库/第一作者 等 - 年份 - 论文标题" \
    --metadata ./library.json --id 条目key \
    --si-doc "第一作者 等 - 年份 - 论文标题 - SI"
```

- **架构分流原则**：
  - **专著教材与复习讲义**：保持原有多章节划分（`01-第一章.md`、`02-第二章.md`、`00-目录.md`），采用几何自然流混排（垂直量化阶梯 $\Delta y = 25$），杜绝插图误置顶与跨页断句破裂。
  - **科研学术文献**：统一默认采用学术标准命名 `{{firstCreator}} - {{year}} - {{title}}.md`；独立 PDF 与 Word 衍生文件只从标题、DOI、首页与文件属性等可核对证据提炼字段，不把 PDF 创建时间或 Office 用户名当出版信息；单篇输出主笔记、`00-目录.md`（URI 编码安全跳转）与 `images/`。
  - **补充材料 (SI) 跨文档双向网络**：传入 `--si-doc` 自动将 `Figure S1`、`Fig. S1`、`Table S1`、`Scheme S1`、`Supplemental/Supplementary Figure 1`、`Supplementary Note 1` 等引用解析为双链：图表指向 SI 中实际生成的 `## Figure S1` 等标题；`Note` 只链接整篇 SI（构建器不生成 Note 标题，避免死锚点）；现有链接、行内代码、围栏代码自动跳过。传入 `--supplement-to` 在 SI 顶部注入回链卡片，并在 frontmatter 建立 `has_supplement` / `supplement_to`。
- **段落边界**：保守保留 OCR 段落与跨页边界，避免误拼题目、公式及新段落。
- **标题与习题精准消歧**：区分名词性小节编号（如 `1. 晶胞概念` 归入 H3）与指令性习题题干（如 `1. 计算这个数`、以 `。？！` 结句或位于习题区者保留为列表/正文），层级结构严谨；拆分章名与传入标题一致时去重；实质脚注和整页图保留，不按 OCR 标签或面积静默丢弃。
- **干净交付**：默认只生成导航、正文 Markdown 和图片；构建状态位于输出旁的 `.<目录名>.build/`，可用 `--state-dir` 指定外部工作目录。
- **可选检索**：仅当用户明确要求后续 Agent 检索、RAG 时添加 `--agent-index`，生成 `agent/` 分块与原页映射。
- **回源修复**：修改前核对原页，通过 `--repairs repairs.json` 提供页码、坐标、旧值、新值和原因；旧值或定位不匹配时停止。文字、脚注、合图及裁框的格式见 `references/mineru-api.md` 的“回源修复图块”一节。图块新增或改框必须从原 PDF 重裁。
- **孤儿图片**：仅通用 `build_markdown.py` 支持 `--prune-orphans`，按所有权记录清理未引用的生成资产；科研入口不接受此开关。保留用户文件，不能直接清空目录。
- **过滤模型泄漏**：自动清除 `The Ground Truth...` 等模型推理遗留文本。
- **扫描件物理边缘噪声排查与清洗**：扫描教材在章节首尾页、装订中缝或页面边缘常残留物理伪影（如防伪印章、条形码乱码、借书章残印、边缘阴影，例如“用应从请勿填清文件中？”等无意义伪字符）。排查时核验章节起始首三行及页边极值位置，通过 `--repairs` 配置 `{"field":"text","old":"...","new":"","reason":"扫描边缘物理印章/条形码伪影"}` 精准清空剔除，严禁让扫描杂质污染章首标题与正式引言。

### 步骤 6：交付前全量校验（核心质量门禁）

**交付前必须跑自动化校验，公式必须 100% 编译通过，绝不抽查：**

```bash
# 1. 结构与资源链接完整性检查
python scripts/validate_output.py ./知识库 --images-dir images [--resource-root <父目录>]

# 2. 抽取全部公式并执行本地 KaTeX 全量编译（要求 0 失败）
python scripts/extract_formulas.py ./知识库 --out formulas.json
node scripts/validate_math.cjs formulas.json
```

跨目录 SI 双链必须传 `--resource-root`（主文与 SI 的共同父目录），否则目标缺失会直接报错而不是放宽。检查围栏未闭合错误与图片遮蔽警告；合法图片语法示例须标注代码语言（如 `markdown`）。校验器会自动遮蔽公式区域，避免将化学式等配位方括号误报为链接失效。源图片候选数、解析图片数与有效引用数含义不同，不能直接要求相等。未引用资产会列出路径，默认保留；重建可用新目录核验，不清空已有知识库。

### 步骤 7：浏览器实际渲染沙箱验收

启动本地离线渲染服务，通过自动化或人工查看确认图片正常、公式报错为 0：

```bash
python scripts/preview_server.py ./知识库 --port 8766 --katex-dir scripts/node_modules/katex/dist
```
- 打开 `http://127.0.0.1:8766/` 验证 `document.documentElement.dataset.ready === "true"` 且 `.math-error` 数量为 0；检查各章实际图片数量与加载状态。加载成功只证明文件可显示，异常图仍须逐幅对照原页确认面板、题注和裁框完整。
- **客户端真实渲染终验**：**“公式语法编译通过 ≠ 客户端显示正常”**。本地沙箱通过后，最终交付必须在实际宿主客户端（如 Obsidian）中核验阅读与实时预览视图，确保没有被 Markdown 语法劫持的伪链接或裸公式。
- **宿主不可用时**：交付报告明确写“自动校验通过，真实客户端终验待完成”，列出未核验项；不能宣称已完成客户端验收，也不为此无限等待。
- **Obsidian 客户端兼容提示**：在瞬间批量写入数百张新插图时，Obsidian 后台文件监视器（File Watcher）可能存在索引延迟，偶见“找不到图片”占位提示。重启 Obsidian 即可触发全库索引扫描并正常渲染。

### 步骤 8：Zotero 同步（只读 API + MCP 写入）

仅用户请求 Zotero 导出或同步时读取 `references/zotero-sync.md` 并执行。HTTP API 只读，写入通过宿主提供的 Zotero MCP 工具；无 MCP 写入能力时交付操作计划，明确同步尚未完成。

```bash
# 默认只读对比，不修改文件
python scripts/zotero_sync.py "文献.md"
```

首次应用须显式选择同步方向；本地与远端冲突时停止。退出码 `2` 表示仍有待执行操作，执行 MCP 写入后必须重跑并回读核验，只有退出码 `0` 且状态 `verified_remote_write` 才能确认远端写入完成。

## 3. 自由度与边界 (Degrees of Freedom)

| 操作维度 | 控制级别 | 规范边界 |
| :--- | :--- | :--- |
| **归一化与语法** | **严格收紧 (Zero Tolerance)** | 坐标转换公式、KaTeX 编译通过率必须 **100%**；严禁出现未闭合定界符、绝对路径或损坏图片链接。 |
| **Zotero 数据回写** | **严格收紧 (Zero Tolerance)** | HTTP 层只读；写入必须经 MCP 工具，且每条操作核对库身份、版本与前置值后回读验证。冲突不自动合并，空值不清空远端。 |
| **文献命名规范** | **严格收紧** | 学术论文默认统一采用 `{{firstCreator}} - {{year}} - {{title}}.md` 标准命名；支持 `--file` 自定义覆盖；禁止使用无意义的 `原文.md`。 |
| **补充材料跨篇双链** | **严格收紧** | 必须采用标准 Obsidian `[[文档#锚点|显示名]]` 语法；跳过代码块与已存在链接，建立 `has_supplement` / `supplement_to` 拓扑双链。 |
| **文档组织分流** | **严格收紧** | 专著教材/复习讲义保持多章节（`01-第一章.md`）分流架构；学术论文保持单篇一体化架构（主笔记+`00-目录.md`+`images/`）。 |
| **多面板碎图缝合** | **分级自适应 (Adaptive)** | 仅同页、同图号或明确 (a)/(b) 面板、空间相邻且中间无正文时自动重裁；跨栏、远距离、缺题注或疑似多图号只保留人工草稿。 |
| **文件完整性** | **严格收紧** | 必须包含 `00-目录.md` 导航入口（标准 URI 编码）；图片全量可解码；严禁破坏性清空输出目录。 |
| **排版与段落合并** | **自适应灵活 (Moderate)** | 根据书籍逻辑组织章节、保守处理段落；子图合并与图题改挂须有原页依据，确认后的图块边界不再自动合并。 |
| **复杂化学/特殊结构** | **工程务实 (Pragmatic)** | 遇到二维环状分子或复杂推导，若 LaTeX 表达失真，优先采用高保真原图局域裁切，确保科学真实性。 |

## 4. 严禁的反模式 (Anti-Patterns)

1. ❌ **一上来就 OCR**：忽略已有矢量文字和高清原图，把简单提取变成低效 OCR。
2. ❌ **破坏性清空目录**：在未获授权或调试子章节时调用 `rmtree`，导致前序成果丢失。
3. ❌ **套用单一模板破坏架构分流**：用论文单篇逻辑套用 500 页教材（导致多章挤压成单篇），或把整页所有插图强制置顶；把页顶首句误判为 H2 标题。
4. ❌ **使用无学术价值的模糊命名**：在学术文献知识库中生成 `原文.md`、`paper.md` 等无作者和年代信息的混乱名称，破坏知识库跨库检索与双向链接。
5. ❌ **公式抽查交付**：认为抽查几页没报错即合格；数千个公式中哪怕 1 个语法错都会导致 Obsidian/前端整块崩溃。
6. ❌ **丢弃表格内嵌图片**：提取表格时使用纯文本截断，导致关键二维码、实验图标全部遗失。
7. ❌ **残留模型提示词**：把 OCR 模型的“The Ground Truth image displays...”等幻觉说明写入知识库。
8. ❌ **盲信 OCR 块原始顺序**：忽略扫描排版与 OCR 提取序列的不一致，长篇教材必须由几何自然流混排，严禁将底部插图置于页首。
9. ❌ **标题公式剥离为裸下划线**：将标题中的 `$\mathrm{CO}_2$` 粗暴降级为 `CO_2`，不仅语法失真，还容易与同行的其他下划线产生 Markdown 斜体冲突。
10. ❌ **把编译无错等同于客户端渲染完成**：在离线沙盒里仅验证 KaTeX 无报错，未校验真实 Markdown 宿主解析器（如 Obsidian）对外层方括号的语法劫持与链接冲突。
11. ❌ **忽略跨平台路径长限制 (Windows MAX_PATH)**：只给最终写入加 `\\?\`，却用普通 `rglob` 枚举，导致超长路径文档根本没有被读取或校验。枚举、读取、写入、原子替换必须走同一套安全路径，目录访问错误不能被静默吞掉。
12. ❌ **静默覆写 Zotero 本地数据库**：绕过版本/前置值校验直接 PATCH；或把本地 API 当可写接口，未回读就宣称同步成功。写入必须经 MCP 工具并回读验证。
13. ❌ **孤立割裂主文与补充材料 (SI)**：将 SI 与主文作为两篇互不相干的文档孤立存放，未提取 S 编号与跨文档双链，导致学术上下文割裂。
